Check the day's prerequisites and report what is missing (MOM-75, docs/mom-75-plan-execution-spec.md section 2.2). This command is read-only: it changes no file, makes no commit, and touches neither production nor Jira. Before each step, say in one line what you are checking. Run commands one at a time.

0. **Repository check.** Run `npm run project:check`. If it exits non-zero, show its one line and stop: these commands belong to `walsh-matthew/momentum-app`, and nothing below runs in another repository.
1. **Working tree.** `git branch --show-current`, then `git status --short`. Expected: a clean tree (`AGENTS.md`, `supabase/.branches/` and `supabase/snippets/` are git-ignored since MOM-68, so they no longer show). Only my uncommitted `docs/FAILURE_LOG.md` and `docs/RAID_LOG.md` may also show. List anything else, including any untracked file, as a problem.
2. **main against GitHub.** `git fetch origin` (it only updates remote-tracking refs), then `git rev-parse main origin/main`. Say whether they match, or whether `main` is behind (a fast-forward fixes it) or has diverged.
3. **Earlier days' work.** `git branch --no-merged origin/main` lists local branches with work that is not in `origin/main`; for each, show `git log origin/main..<branch> --oneline`. Check `gh --version`: if `gh` is installed, run `gh pr list --state open`; if not, say "gh is not installed: check open pull requests on GitHub".
4. **The plan.** Run `npm run plan:check`. Report its errors and warnings in plain words. Then print the "Today's runbook" section of `docs/plans/NEXT_BUILD_PLAN.md`.
5. **Environment, by name only, never printing a value.** For each variable name listed in `.env.example` (lines like `NAME=`), check that `.env.local` has a line starting with `NAME=` using `grep -q` (no output). List the missing names, but judge each: a name is a problem only if a session note or block in the plan needs it, or it is a `NEXT_PUBLIC_` or Supabase name. Some are deliberately unset locally (for example the model key, which the browser tests refuse to run with), so say "not set here; fine unless a block needs it" for those instead of raising an alarm. If any session note in the plan mentions Docker and a block that needs the local stack is on the runbook, check that Docker is running. When Docker is checked, also run `npm run stack:status` and report its one line ("Local Supabase stack: running" or "not running"); never run `supabase status`, whose output holds the local stack's keys.
6. **Manual, not checkable here.** Print: "Standing smoke-test account: confirm in the Supabase dashboard (Authentication, Users) that `smoke-test@momentum-app.test` exists and is the only user. This cannot be verified without production credentials, so it is not checked." Also: "Vercel project and branch protection: confirm in the dashboards if you changed them." Also: "Turn on `/remote-control` (`/rc`) once a day to mirror this session to your phone (survives `/clear`); In `/config`, turn on both \"Push when actions required\" and \"Push when Claude decides\". The day-loop commands ask for a push at each planned stop; pushes are skipped while this terminal has focus."
7. **Summary.** One list: ready, or what to fix first. Under it, repeat the two reminders from step 6, because this is where I read before the first block: "Turn on `/rc` (`/remote-control`) now to mirror this session to your phone" and "In `/config`, turn on both \"Push when actions required\" and \"Push when Claude decides\". The day-loop commands ask for a push at each planned stop; pushes are skipped while this terminal has focus". Then: "Next: `/run-block <MOM-n>` for the first block in the runbook."
