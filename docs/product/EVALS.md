# Momentum evals

How Momentum checks the places Claude is used. The rules being checked are in [`docs/DOMAIN_MODEL.md`](../DOMAIN_MODEL.md) §2.1; this file links to them and does not copy them. Claude never scores and never does math (§1.7), so what is evaluated is its words and its drafts, not the numbers. This file is non-binding, names its sources in each section and holds no prices, cost figures or thresholds: those live outside the repo (`tests/pm-docs-sources.test.ts` checks the sources, MOM-164).

## 1. What's evaluated

*Sources: design record `docs/design/2026-10-26-goal-model-design.md` §5.1 and §6.2; `docs/DOMAIN_MODEL.md` §2 and §3; `docs/LLM_GOVERNANCE.md` ("The weekly review's one line"); `lib/review/reflection.ts`; `lib/ai/review.ts`; `lib/setup/returning.ts`; `tests/live/setup-add.live.ts`; Jira MOM-111, MOM-113, MOM-132.*

- **Now: the setup conversation** (MOM-111). Every turn of Claude's passes through the rule checks and the plain-words checks, and the final draft must pass the same schema validation as the saved model (§2.3).
- **Now: adding a goal or a target after setup** (MOM-132, PRs #94 and #99). The same conversation, held to what is not saved yet: a saved topic is skipped in code's words and never sent to Claude, the draft leaves saved facts as they were, and the checks in section 2 gain four `returning.*` codes. A live runner exists (`tests/live/setup-add.live.ts`, local stack only).
- **Now: the weekly review's layer 2 line** (MOM-113 block 3.3, merged in PR #79). Claude writes one plain sentence about the week from a fact list the engine builds (target titles, where each ended as a word, what crossed, pattern kinds, trend direction, tone; no counts, dates or numbers to repeat), and code checks the sentence before it is shown (§3.3). It is asked for only when the person taps, on a small per-person daily limit set in `docs/LLM_GOVERNANCE.md`. Since MOM-113 block 3.4 (PR #92) its prompt asks for warmth (a kind friend who has been following along); the rules, checks, fallback lines and fields sent did not change. The checks are in section 2.

## 2. Quality bar

*Sources: `lib/setup/cards.ts`, `lib/setup/cardTurns.ts` and `lib/setup/evals.ts` (MOM-178); `lib/setup/weekCards.ts` and `tests/setup-week-cards.test.ts` (MOM-179); `lib/setup/checks.ts` (read for this fill, again for MOM-164: the `returning.*` codes, and again for PR #115: the unit codes); `lib/setup/units.ts` (MOM-176); `lib/setup/validate.ts`; `lib/setup/feedback.ts`; `lib/setup/evals.ts`; `lib/setup/returning.ts`; `docs/DOMAIN_MODEL.md` §2.1 (hard rules and plain language); MOM-111 comments 2026-10-29 and 2026-10-30.*

The bar is the eight hard rules ([`DOMAIN_MODEL.md` §2.1](../DOMAIN_MODEL.md)), the draft rules and the plain-words checks. The checks are heuristics over words and structure, not language understanding, and they err toward flagging (`lib/setup/checks.ts` header). A reply that breaks a hard rule or a draft rule is thrown away and asked for again with fixed words saying which rule failed. A plain-words failure gets one retry and then the reply is shown and the rule logged, so a plain-words check never ends a setup in "Try again" (`checks.ts` header; `DOMAIN_MODEL.md` §2.3).

| Rule | Code(s) | What the check catches |
| --- | --- | --- |
| One question per turn | `one_question.none`, `.marks`, `.no_mark`, `.hidden`, `.sentences`, `.joined`, `.options` | No question, not exactly one question mark, no mark at the end, a question hiding outside the question field, more than one sentence, two asks joined, options on a kind of turn that lists none |
| Assume nothing | `assume_nothing.word`, `.changed` | A day or clock-time word the person did not say; a draft value that changed without the person's newest answer |
| No announced reminder | `no_announced_reminder` | Claude announced a reminder, check-in or nudge instead of asking |
| Choice before examples | `choice.ideas_unasked`, `.offer_words`, `.offer_examples`, `.examples` | Ideas given without being asked for; an offer without the choice; examples inside the offer; examples in a question that needs the choice first |
| Skip what is answered | `skip.repeat`, `.unanswered`, `.long`, `.not_asked` | A topic asked again; a skip of a topic not yet answered; a skip notice longer than one short line; since MOM-178, a question of Claude's on a topic the screen asks with its own card (tone, celebrations, review depth, review and planning) or that setup no longer asks at all (reminders, check-ins, quiet times, balance mentions). Since MOM-168 `answeredTopics` also reads a target's floor, aspiration, source, metric, days and deadline date, and the goal's shape, dates, block length, return and can-move answer, so a skip of something said inside another answer ("runs, at least 3 a week") is accepted (`lib/setup/leaves.ts`) |
| Numbered interpretations | `interpretations.count`, `.guessed`, `.changed` | Not two to four readings; guessing when the answer did not fit; the draft changing on an answer that did not fit |
| Chunked playback | `playback.words`, `.final_changed`, `.no_chunk`, `.stray_chunk`, `.early_final`, `.final_long`, `.unapproved`, `.changed_after` | Claude writing playback words (code writes them); the model changing during the final confirmation; a part marked approved without being played back; the final confirmation before every part was approved or too long |
| No math | `math.score`, `.arithmetic`, `.number` | Claude scored or graded; did arithmetic; wrote a number the person did not say |
| Draft | `draft.no_source`, `.not_said`, `.not_accepted`, `.rule` | After every turn the draft must validate; a value with no source in the conversation is asked for in that turn, never guessed again |
| Plain words | `plain.lead_in`, `.question_long`, `.activity`, `.date_lead_in`, `.date_asks`, `.options_say`, `.jargon`, `.unquoted_source`, `.title`, `.asked_again`, `.level_no_number` | A lead-in that previews the question or runs past one short line (110 characters); a question over 14 words; an activity the person never said; a date repeated in the lead-in, or shown and then asked for; a lead-in over 60 characters on a card of options; model words (floor, aspiration, baseline) the person never said; a line pointing at an earlier answer without quoting it; a new goal, target or work-item title (or kind of day) that reads as a sentence rather than a short name (`lib/setup/titles.ts`, MOM-167 part 1: one retry, then shown); a question asked for a topic the draft already holds that was never asked or skipped with a line, because the person gave it inside another answer (`checkAskedAgain` in `lib/setup/checks.ts`, MOM-168: one retry, then shown; the topic tag decides, so a mislabelled question is not caught; playback, final, ideas, interpretations and proposal turns are never checked); the question on which level a number is (`number_level`: "Is that the least that counts, or what you're aiming for?") that does not quote the number the person gave (`checkLevelQuotesNumber`, MOM-168) |
| Adding after setup (MOM-132) | `returning.topic`, `.person`, `.goal`, `.chunk` | A saved topic asked again; the draft changing a saved person fact or setting; a second goal added while adding targets to one, or the saved goal changed; a part that is already approved played back or un-approved |
| Option lists | `choice.ideas_context`, `.ideas_bare`, `.ideas_scale`, `.ideas_role`, `.ideas_words` | An offer of ideas with no detail line; an option that is a bare number; a run of five or more consecutive numbers; a number option that does not say which number it sets; an option counting a thing the person did not say |

Since PR #115 (MOM-167's title-check fix, 2026-11-02): a unit mistake in the draft has its own code, `draft.unit_extra` (a unit on a count, a time or a checklist) or `draft.unit_missing` (a quantity with no unit), and its retry says which way to fix it (`lib/setup/validate.ts`, `lib/setup/feedback.ts`); a title whose clean version reads as a sentence keeps the title, so `plain.title` never judges a sentence that will not be shown; and a retry repeats every rule broken on earlier tries of the same turn. Since MOM-176 (2026-11-03): code clears a unit Claude puts on a count, a time or a checklist before the turn is checked (`lib/setup/units.ts`, run in `runCheckedTurn`), so that slip no longer throws a turn away or spends a retry; `draft.unit_extra` stays as the check on a saved session and the final save, and a quantity with no unit is still sent back (`draft.unit_missing`).

**The weekly review's layer 2 line** (MOM-113 block 3.3, PR #79; `lib/review/reflection.ts`, read for this update). A separate, smaller set of checks, run in code on the raw reply. A reply that fails is asked for again once, with a fixed note naming the rule; a reply that fails twice is replaced by a line written by code and labelled as Momentum's, so a failed check never ends the review (`REFLECTION_RETRY_NOTES`, `REFLECTION_FALLBACK_LINES`). The person's own target titles are taken out before the checks, because a title can hold a digit or a word that looks like an ask.

| Rule | Code | What the check catches |
| --- | --- | --- |
| Readable reply | `unreadable`, `empty` | A reply that is not the JSON object `{"line": ...}`; an empty line |
| One short sentence | `too_long`, `not_one_sentence` | More than 200 characters; more than one sentence or more than one line |
| No question | `question` | A question mark |
| No numbers | `number` | A digit or a number word (the facts give Claude no number to repeat, §1.7) |
| No score | `score` | A percent sign, or score, grade, rating or point words |
| No ask | `ask` | A whole-word ask or suggestion (try, consider, should, remember, aim and similar); "retry" and "entry" do not count |
| Plain text | `markup` | Formatting marks |
